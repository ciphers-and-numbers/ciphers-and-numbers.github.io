# 주제선택 "암호와 수" 수업자료 홈페이지 — 작업 정리

새 대화에서 이어서 작업할 때 이 문서를 먼저 읽는다.
이 저장소는 공개이므로 이 문서에도 정답, 학생 정보, 개인 메일 주소를 적지 않는다.

## 1. 목표

학생이 링크로 접속해 활동지와 슬라이드에 입력하고 제출한다.
제출 결과는 선생님의 구글 시트에 자동 저장되고, 이를 바탕으로 집계와 서술형 분석을 한다.
차시를 계속 추가하고 고칠 것이므로, 파일 생성부터 목차 갱신, 커밋, 푸시, 앱스크립트 재배포까지 Claude에게 한 번에 맡길 수 있는 구조로 만든다.

## 2. 지금까지 끝난 일

- 저장소를 조직 `ciphers-and-numbers`로 옮기고 이름을 `ciphers-and-numbers.github.io`로 바꿨다.
- 홈페이지 주소는 `https://ciphers-and-numbers.github.io/` 이다. (Pages: main 브랜치 / root)
- GitHub 메일 가리기 설정 두 가지를 켰다.
- 선생님 개인 구글 계정에서 Google Apps Script API를 켰다.
- 구글 드라이브 자료 폴더 이름을 "주제선택_암호와_수"로 바꿨다.

## 3. 확정된 결정

**계정**
시트와 앱스크립트는 선생님 개인 구글 계정으로 만든다. (학교 Workspace 계정은 쓰지 않는다)

**대상과 학생 구분**
1학년 대상이고, 1~6반 학생이 섞여서 듣는다. 로그인 없이 학번 5자리만 받는다.
학번 형식은 ABBCC(학년 1자리, 반 2자리, 번호 2자리)이다.
받는 범위는 학년 1, 반 01~06, 번호 01~30으로 제한하고, 형식이 틀리면 화면에서 바로 다시 입력하게 한다.

**접속 기기**
갤럭시탭을 가로로 놓고 쓴다. 문제·그림은 왼쪽, 풀이·개념 설명은 오른쪽에 두고, 세로 화면에서는 위아래로 바뀌게 한다.

**입력 방식**
선택형과 글자 입력이 기본이다. 손으로 그리는 그림·그래프 칸도 공통 틀에 미리 넣어 둔다.
그림은 구글 드라이브 폴더에 이미지로 저장하고 시트에는 링크를 남긴다. 승인을 한 번으로 끝내려고 드라이브 저장 권한을 처음부터 포함한다.

**다시 제출**
제출할 때마다 새 줄로 모두 쌓는다. 마감 기능은 넣지 않는다.
평가는 여러 번 낸 것 가운데 가장 잘된 것으로 하고, 학생별 최고 제출 요약은 분석 단계에서 만든다.

**자동 채점과 피드백**
선택형은 버튼을 누르면 바로 맞음/틀림을 간단히 보여 준다.
정답은 HTML에 넣지 않는다. 학생이 버튼을 누르면 앱스크립트가 시트의 "정답" 탭과 비교해 결과만 돌려준다. (1~2초 걸림)
틀리면 다시 고를 수 있고, 몇 번 만에 맞혔는지 기록한다.
단답은 정답 탭에 `답1|답2`처럼 여러 답을 허용하고, 띄어쓰기 차이는 무시한다.
서술형은 점수를 매기지 않고 저장한 뒤, 분석은 데이터를 내려받아 따로 한다. 핵심 낱말 포함 여부 표시는 선택 사항이다.

**시트 구성**
차시마다 탭 하나를 둔다.
모든 탭의 앞쪽 열은 제출시각, 차시, 학번, 제출 횟수로 같게 하고, 그 뒤에 차시마다 다른 문항 열, 맨 끝에 점수 열을 둔다.
문항 열 제목은 첫 제출 때 앱스크립트가 HTML의 문항 이름으로 자동으로 만든다.
그 밖에 "정답" 탭(학생 비공개), 차시별 제출 인원·평균을 모으는 "요약" 탭을 둔다.

**전송 방식**
HTML에서 앱스크립트로 보낼 때 `Content-Type: text/plain`으로 JSON 문자열을 POST한다. (CORS 사전 확인 요청이 생기지 않는 방식)
네트워크 오류 때는 브라우저에 임시 보관했다가 다시 보낸다.
웹앱 주소는 공통 제출 파일 한 곳에만 적는다.

**앱스크립트 관리와 배포**
코드는 저장소의 `apps-script/` 폴더에서 clasp로 관리한다.
clasp 로그인 정보는 선생님 PC에서 한 번 만들어 GitHub 저장소 Secrets에 넣고, GitHub Actions가 `clasp push`와 `clasp deploy -i <기존배포ID>`를 자동으로 실행한다.
재배포는 항상 기존 배포의 버전만 올려서 웹앱 주소를 바꾸지 않는다.
웹앱은 "실행: 나 / 접근: 모든 사용자"로 배포하고, 처음 한 번은 선생님이 권한 허용을 누른다.

**홈페이지 방향**
"암호와 수" 전용 홈페이지로 바꾼다. 일차함수 앱(`linear-function/`)은 목록에서 뺀다.
과목 버튼 등 다른 메뉴는 일단 그대로 두고 나중에 필요에 따라 고친다.
분위기는 학교 수업에 맞게 차분하고 단정하게 한다.

**차시 페이지(슬라이드) 만들기 원칙** — 매번 지킨다
차시 페이지는 슬라이드 형식으로 만들고, 학생 입력칸과 제출 기능을 항상 넣는다. (`common/submit.js` 사용)
슬라이드에는 날짜와 차시 번호를 넣지 않는다. 드라이브 파일 이름의 날짜는 실제 수업일과 다를 수 있다.
학교 이름, 반·번호·이름 칸은 공개 페이지라서 넣지 않는다. 학생 구분은 제출 화면의 학번으로 한다.
바로 채점할 문항에는 `data-check` 확인 버튼을 단다. 그 문항의 정답은 Claude가 구글 시트 연결 도구로 시트 "암호와_수_제출"의 "정답" 탭에 직접 넣고, 슬라이드를 고치면 정답 탭도 함께 고친다. (정답은 저장소에 넣지 않는다)

`common/submit.js`를 고치면 차시 페이지의 `<script src="../common/submit.js?v=번호">` 번호를 올린다. (GitHub Pages가 10분쯤 옛 파일을 보여 주기 때문)
홈페이지의 `style.css`, `site-config.js`, `script.js`, `hero-reel.js`를 고치면 `index.html`에서 해당 파일의 `?v=번호`를 올린다.
`apps-script/Code.gs`를 고치면 선생님이 편집기에 붙여 넣고 "배포 관리 → 새 버전"으로 배포해야 반영된다.

평가는 점수가 아니라 선생님이 문장(특기사항)으로 쓴다. 시트의 "점수" 열은 참고용으로만 남겨 두고, 문장 초안을 만들 때는 서술형 답, "(시도)" 열, 제출 횟수를 근거로 쓴다.

**세부특기사항 작성 때 함께 볼 종이 활동지 기록**
- 2기 종이 활동지는 선생님 드라이브의 구글 시트 "암호와수_2기_활동기록"에 차시별 탭으로 옮겨 둔다. (지금은 "스키테일" 탭, 25명)
- 한 줄이 학생 한 명이다. 활동별 답, 짝과 주고받은 격자·해독, 앞면 성찰, 뒷면(영상 보고 쓴 글)이 들어 있다.
- 맨 끝 "판독 메모" 열에서 각 칸을 어떻게 읽었는지 알 수 있다.
  - "선생님 확인": 선생님이 원본을 보고 직접 확인한 칸
  - "다른 전사본 참고해 고침"·"선생님 지시로 다른 전사본 판독을 따름": 선생님이 따로 준 전사본(사람마다 읽은 결과가 다를 수 있음)에 맞춘 칸
  - [?]: 끝까지 읽지 못한 글자
  - "결석 후 나중에 따로 작성함": 수업 날 결석하고 뒤에 쓴 학생
- 세특 초안에는 [?]가 있는 문장을 그대로 인용하지 않는다. 짝 메시지처럼 사적인 내용(친구 이름, 장난 글)은 세특에 쓰지 않고, 활동에 참여한 모습과 수학적 생각(배수·약수, 면 수 후보, 약점 분석)만 근거로 쓴다.
- 이 저장소에는 학생 이름이나 활동 내용을 넣지 않는다. 기록은 시트에만 둔다.

수업 시간 기준: 오리엔테이션을 뺀 차시는 한 슬라이드 묶음이 45분 2차시(90분) 분량이다. 앞뒤 준비·정리 20분을 빼고 **필수 활동만 더해 70분 이상**이 되게 한다(선택 슬라이드는 따로). 슬라이드마다 시간을 적고, 첫 화면 "오늘 할 일"의 시간 합이 슬라이드 시간 합과 같게 맞춘다. 오리엔테이션은 1차시로 보고 37분.

슬라이드와 웹앱(탭 형식 포함) 모든 페이지의 이전·다음 바는 화면 맨 아래에 고정한다. 내용 길이에 따라 버튼 위치가 오르내리면 안 된다. 새 페이지도 `common/deck.css`의 `.deck-nav`와 같은 모양(position:fixed, 아래 여백 96px)을 쓴다.
학번은 첫 슬라이드에서 입력받고(`#studentId`), 제출하기 버튼은 마지막 슬라이드에 둔다. 제출 화면에는 입력한 학번을 보여 주고 "학번 바꾸기"로 첫 슬라이드로 돌아가게 한다.
아래쪽 바에 슬라이드별 진행 점(`#deckDots`)을 두고, 제출 화면에 빈칸이 있는 슬라이드로 가는 버튼(`#emptyList`)을 둔다. 선택 활동 슬라이드에는 `data-optional`, 상황에 따라 비워도 되는 칸에는 `data-free`를 붙인다.
영상 구간은 YouTube IFrame API로 지킨다. (구간 밖으로 넘기면 구간 안으로 되돌림)
유튜브 영상은 youtube-nocookie 주소로 넣고 start·end로 필요한 구간만 재생한다. 영상 오른쪽에는 서술형 질문 칸을 두고, 슬라이드를 넘기면 영상이 멈추게 한다. (학교에서 유튜브 재생 가능 확인함)

**자료 전달**
선생님이 구글 드라이브 "주제선택_암호와_수" 폴더에 자료를 올리고, Claude는 거기서 읽는다.
줄 자료는 수업계획표, 실제 사용한 활동지와 슬라이드(HTML), 수업 관련 유튜브 영상 링크이다.
1기 학생 스캔본은 해당 차시를 만들 때 그 차시 것만 3~5장 받는다. 저장소에는 넣지 않는다.

## 4. 수업 현황

총 17차시이다. 1기는 종이 활동지로 수업을 마쳤고, 2기가 진행 중이다.
첫 한 바퀴("입력 → 제출 → 시트 저장")는 다음 수업 차시로 만든다.

## 4-1-1. 남은 2기 일정 메모

남은 슬라이드는 계획서 순서대로 만든다: 모스 부호와 이진법 → 바코드와 QR코드 → 소수와 RSA → 나만의 암호 설계와 AI 비밀 대화 → 암호 업그레이드와 해독 대결 → 포트폴리오 포스터와 성찰.
다만 2기는 12월 10일 전까지 "암호 만드는 활동"을 마쳐야 해서, 실제 수업은 슬라이드 순서와 다르게 진행될 수 있다. (선생님이 수업 때 조정. 슬라이드는 계획서대로 만들어 둔다)

## 4-1. 진행 상황

- 두 번째 학생 웹앱 `mirror-cipher/`(10608 학생의 거울 암호, A = 1부터 번호)를 만들었다. 1기 10/6 요약에서 고름. 단계: 거울 규칙 찾기 → 메시지 풀기와 두 번 비추기 실험 → 자기 자신이 되는 글자 찾기 → 거울 + k칸 밀기 업그레이드 → 짝의 암호 풀기·푼 수 세기 → 제출. 실험 도구는 해당 도전을 맞힌 뒤에만 열어 답을 미리 볼 수 없게 함. 정답 탭 등록.

## 6. 작업 방식 약속

- 답변은 "~입니다"체로, 표 대신 줄글과 줄바꿈으로 쓴다.
- 문장이 한 줄에 들어가면 한 줄로 쓰고, 넘칠 때만 의미 단위로 줄바꿈한다. 한두 글자만 아래로 떨어지지 않게 한다.
- 코드 실행이나 테스트는 선생님이 요청할 때만 한다.
- 정답, 학생 학번·이름, 제출 데이터, 개인 메일 주소는 저장소에 넣지 않는다.
- 세 번째 학생 웹앱 `two-key-cipher/`(10102 학생의 두 열쇠 암호, A = 0부터 번호)를 만들었다. 1기 10/19 "해독 대결" 요약에서 고름(홀수 번째와 짝수 번째 글자를 다르게 미는 업그레이드). 단계: 규칙 찾기 → 메시지 풀기(0보다 작아질 때 26 더하기) → 시저 암호와 비교(같은 글자가 다르게 바뀜, 열쇠 가짓수) → 나만의 두 열쇠와 짝의 암호 풀기 → 열쇠 없이 풀기(두 열쇠를 따로 찾으면 훨씬 적은 횟수) → 마무리. 비교 도구와 비즈네르 암호 이야기는 해당 도전을 맞힌 뒤 열린다. "두 열쇠 암호"라는 이름은 학생이 붙인 것이 아니라 웹앱을 만들며 붙였다. 카드·썸네일에는 칸 수를 넣지 않는다.
- 전체 점검: 홈 화면 용어를 "자료"로 통일, 휴대폰에서 누르는 범위 확대(웹앱 확인 버튼, 별점, 진행 점, 영상 링크), 이름표 없는 입력칸에 aria-label 자동 부여(submit.js v7), 긴 암호문 줄바꿈.
- 네 번째 학생 웹앱 `multiply-cipher/`(10611 학생의 곱셈 알파벳 암호, A = 1부터 번호)를 만들었다. 1기 10/19 요약에서 고름(이름도 학생이 붙인 그대로). 홀수 번째와 짝수 번째 글자 번호에 서로 다른 수를 곱하고 26을 넘으면 26을 뺀다. 학생이 해독 대결에 낸 실제 암호문을 요약의 규칙으로 계산해 보니 그대로 맞아서, 도전 3을 푼 뒤 열리는 문제로 넣었다. 단계: 곱하는 수 찾기 → 26을 넘으면(몫과 나머지) → 거꾸로 풀기(26을 더해 배수 찾기, 해독 도우미) → 아무 수나 곱해도 될까(2를 곱하면 글자가 겹침, 26 = 2 × 13과 공약수) → 나만의 곱셈 열쇠와 짝의 암호 풀기 → 마무리. 쓸 수 없는 수(2의 배수, 13의 배수)를 열쇠로 넣으면 막는다.
- 알파벳 번호표는 26칸을 한 줄로 두면 휴대폰에서 반만 보이므로 13칸씩 두 줄로 나눈다(`table.nums.split`). 일차식·두 열쇠·곱셈 웹앱에 적용.
- 다섯 번째 학생 웹앱 `prime-stair-cipher/`(10404 학생의 소수 계단 암호)를 만들었다. 1기 10/6 요약에서 고름(이름은 학생이 붙인 그대로). 한글 기본 자음 14개(1~14번)와 기본 모음 10개(15~24번)에 번호를 붙이고 같은 수를 더하는 암호이며, 학생이 성찰에 쓴 개선안 "글자 순서마다 서로 다른 소수를 더한다"를 도전 4·5에서 "첫째 자모에 첫째 소수, 둘째 자모에 둘째 소수…"로 구현했다(이 구체적인 방식은 웹앱을 만들며 정한 것). 단계: 더한 수 찾기 → 한글 메시지 풀기(받침) → 열쇠 없이 풀기 → 소수 계단 → 나만의 계단(시작 소수가 열쇠)과 짝의 암호 → 마무리. 쌍자음·복모음이 든 낱말은 막는다. 자동 문제 낱말은 기본 자모만으로 된 것만 쓴다.
- 확인 버튼: 한 줄 입력칸에서 엔터를 누르면 확인되고, 답을 고치면 예전 채점 표시가 지워진다(submit.js v8).
- 웹앱에서 "정답이면 도구 열기"는 맞음으로 바뀌는 순간에 한 번만 실행해야 한다. 확인 버튼과 여는 상자가 같은 패널에 있으면 관찰 코드가 자기 변경을 다시 감지해 화면이 멈춘다(소수 계단 웹앱에서 발견해 고침).
- 학번 검색: 홈 검색창에서 학생 작품을 만든 학생의 학번으로 찾을 수 있다. `site-config.js`의 학생 작품 항목에 `maker: "10406"`처럼 학번을 적는다(이름은 쓰지 않음). "10406", "104"(1학년 4반), "4반 6번", "1학년 6반", "1-4-6" 같은 검색어를 알아듣고, 카드에 "만든 학생 10406" 표시가 붙는다. 띄어 쓴 낱말은 모두 들어 있는 자료만 나온다. 새 학생 웹앱을 올릴 때 `maker`를 꼭 넣는다.
- 여섯 번째 학생 웹앱 `keypad-cipher/`(10517 학생의 휴대폰 자판 암호)를 만들었다. 1기 10/6·10/19·10/27 요약에서 고름(이름은 학생의 암호 카드 이름 그대로). 천지인 자판의 버튼 번호와 누르는 횟수(점)로 한글을 나타내고, 해독 대결에서 한 "숫자마다 2 더하기" 업그레이드를 도전 4·5에 넣었다. 요약에는 표기 방법이 자세히 없어서, 모음은 천지인 획(ㅣ=1, ㆍ=2, ㅡ=3)을 누르는 차례대로 쓰고, 글자 사이는 빗금으로 나누고, 9를 넘으면 10을 빼는 것으로 정했다(웹앱을 만들며 정한 것). 단계: 버튼과 점 → 메시지 풀기 → 순서쌍 (버튼, 횟수)와 "점이 없으면 00을 두 가지로 읽는다" → 버튼 번호 밀기 → 나만의 열쇠와 짝의 암호(화면 버튼으로 입력, 마침표로 써도 읽음) → 마무리.
- 새로고침해도 맞힌 문제의 "맞음" 표시가 되살아난다(답이 그대로일 때만). 그래서 웹앱의 별과 열린 도구도 새로고침 뒤에 그대로 남는다(submit.js v9).
- 메인 화면 입구의 암호 문제(`gate.js`): QR이나 주소로 메인에 들어오면 시저 암호 한 문제(여러 문제 가운데 무작위)를 풀어야 자료 목록이 보인다. 한 번 풀면 그 기기에서는 다시 묻지 않는다(`localStorage`의 `cn-gate`). 두 번 틀리면 첫 글자 힌트, 네 번 틀리면 두 글자 힌트가 나오고 "다른 문제로 바꾸기"가 있다. 서버가 없는 홈페이지라 진짜 잠금은 아니다. 차시와 웹앱 주소를 직접 열면 그대로 열리며, 일부러 그렇게 두었다(수업 중 차시 QR 흐름을 막지 않기 위해). 문제 목록에는 암호문과 민 칸 수만 적고 정답 낱말은 적지 않는다(입력한 낱말을 다시 암호로 바꿔 비교).
- 웹앱 6개에 "번호표" 버튼(휴대폰 자판 암호는 "자판", 거울 암호는 "거울판")을 화면 오른쪽 아래에 고정했다. 어느 단계에서나 눌러 번호표를 볼 수 있어 앞 단계로 넘겨 보지 않아도 된다. 새 웹앱에도 같은 버튼을 넣는다. 소수 계단 암호는 도전 3·4·5 안에도 번호표를 직접 넣었다.
- 홈 검색창: 휴대폰에서 검색창이 납작하게 눌리고 "초기화"만 크게 보이던 것을 고쳐, 검색창과 초기화를 한 줄에 나란히 두었다. 검색창 아래에 학번 검색 예시 한 줄을 넣고, 검색창을 누르면 테두리로 표시된다. 휴대폰 자판 암호 썸네일은 왼쪽 위 번호표에 가려지지 않게 자판을 오른쪽으로 옮겼다.
- 일곱 번째 학생 웹앱 `bracket-cipher/`(10516 학생의 괄호 암호, A = 1부터 번호)를 만들었다. 1기 10/6·10/27 요약에서 고름: 번호에 2를 더한 뒤 3을 곱하고 26을 넘으면 26을 빼는 (A+2)×3 규칙. 학생은 이 암호를 "시저"라고 불렀고, "괄호 암호"는 웹앱을 만들며 붙인 이름이다. 단계: 두 가지 계산 찾기(괄호가 없으면 답이 달라짐) → 식으로 쓰기(분배법칙)와 암호화 → 거꾸로 풀기(계산도 순서도 거꾸로) → 순서를 바꾸면 다른 암호, 열쇠 가짓수 → 나만의 두 단계 암호와 짝의 암호 → 마무리. 도전 1의 오른쪽 활동은 곱한 수와 더한 수를 맞힌 뒤에 열린다(답이 먼저 보이지 않게).
- 괄호 암호 웹앱 마무리: 시트 "정답" 탭에 `bracket-cipher` 정답 15개를 등록하고, 휴대폰 폭에서 채점(15문항 모두 맞음)·제출·새로고침 뒤 표시 유지까지 시험한 다음 시험 기록(10630)을 지웠다. `site-config.js`에 항목을 추가해(`maker: "10516"`) 홈페이지 목록에 올리고 main에 배포했다.
- 노션 영상 모음을 다시 검토해 선택 영상 슬라이드 4장을 넣었다(모스 3번, 소수와 RSA 3번, 바코드 5번, 스키테일 3번 슬라이드). 제목에 "(선택)"을 붙이고 질문 칸은 모두 `data-free`라 비워도 빈칸으로 세지 않는다. 슬라이드가 한 장씩 늘어 그 뒤 슬라이드 번호가 1씩 밀렸으므로, 노션 등에 적어 둔 `#번호` 링크는 다시 맞춰야 한다. 새 구간은 노션에 적힌 시각을 따랐고, 이 환경에서는 유튜브를 열 수 없어 실제 재생은 확인하지 못했다(수업 전에 한 번씩 재생해 볼 것). 아직 넣지 않은 후보: 참쌤스쿨 손동작 영상(표가 진짜 이진수가 아님을 안내해야 함), 티전드 자물쇠 비유, "암호일까 부호일까" 성찰 질문.
- 영상 원칙: 슬라이드의 중심은 활동이다. 영상은 짧은 소개나 설명으로만 쓰고 많이 넣지 않는다. 새 영상은 선생님이 요청할 때만 넣고, 넣더라도 한 차시에 필수 영상은 1~2편, 한 편은 1~2분 구간으로 한다. 손동작 영상과 자물쇠 비유 영상 후보는 넣지 않기로 했다.
- 영상 대신 활동으로 반영: 노션 요약의 "부호와 체크숫자는 내용을 숨기는 암호화가 아니다"라는 구분을 성찰 질문으로 넣었다(모스 `성찰 암호일까 부호일까`, 바코드 `성찰 숨기기와 확인하기`). 노션 요약 페이지의 슬라이드 링크 번호도 새 번호로 맞췄다.
- 영상 줄이기: 위 원칙에 따라 영상 슬라이드 5장을 뺐다. 시저 암호의 한글 암호판·에니그마 영상(에니그마는 해독 대결 차시에만 남김), 그리고 앞서 넣었던 선택 영상 가운데 모스 SOS·에라토스테네스의 체·ISBN. 스키테일 시연(문제·풀이 두 칸)만 남겼다. 뺀 영상의 내용은 활동으로 옮겼다: 모스 부호표의 "SOS를 넣어 들어 보세요" 안내, 체 활동의 질문 `활동1 2는 남기고 4의 배수는 건너뛰는 까닭`, 진짜 바코드 검산에 "책 번호(ISBN)도 같은 규칙" 안내, 시저 성찰의 `성찰 열쇠가 바뀌는 시저 암호`. 지금 차시별 영상은 시저 2, 모스 2, 바코드 2, 소수와 RSA 2, 스키테일 2(영상 칸 3), 해독 대결 2, 오리엔테이션 1, 나만의 암호 1편이다. 슬라이드 번호는 모스·소수와 RSA·바코드가 영상을 넣기 전으로 돌아갔고, 시저는 한글 자음 시저 암호부터 번호가 당겨졌다. 시트 caesar-cipher 탭의 `영상3 …`, `영상4 …` 열은 이제 쓰지 않는 열이다(지난 제출 기록이 있을 수 있어 지우지 않음).
- 여덟 번째 학생 웹앱 `caesar-prime-cipher/`(10514 학생의 시저 소수 암호, A = 1부터 번호)를 만들어 목록에 올렸다. 1기 10/6·10/19 요약에서 고름: 처음에는 모스 부호의 점을 0, 선을 1로 바꾸는 암호였는데 AI가 규칙 없이 풀었고, 해독 대결 시간에 "시저 암호로 바꾼 뒤 그 글자의 소수 번호로 다시 바꾸는" 암호로 업그레이드했다(이름은 학생이 붙인 그대로). 미는 칸 수는 요약에 없어서 웹앱을 만들며 정했고, "글자 번호 n → n번째 소수"로 바꾸는 것으로 구현했다. 단계: 두 단계 찾기(암호 수가 몇 번째 소수인지 → 민 칸 수) → 암호로 바꾸기(끝 글자는 처음으로 돌아감, 수를 붙여 쓰면 여러 가지로 읽힘) → 거꾸로 풀기 → 소수라서 좋은 점(소수가 아닌 수가 섞이면 잘못 전해진 것을 안다, 체크숫자와 비교)과 아쉬운 점(열쇠는 여전히 칸 수뿐) → 나만의 열쇠와 짝의 암호 → 마무리. 암호문은 수를 띄어 쓰고, 쉼표로 써도 읽는다. 번호표 버튼에는 알파벳 번호와 소수 번호표(26번째까지)가 함께 나온다. 정답 탭에 14문항 등록, 휴대폰 폭에서 채점(14문항 모두 맞음)·제출·새로고침 뒤 표시 유지까지 시험하고 시험 기록을 지웠다. 카드·썸네일에는 칸 수와 답을 넣지 않았다.
- 영상 구간 검증: 이 환경에서는 유튜브가 봇 확인으로 막혀 재생과 자막을 볼 수 없다. 그래서 선생님이 브라우저 도우미로 실제 재생해 확인하고, 결과를 노션 "암호 수업 영상 2편 · 세 구간 검증 결과"(영상 모음 아래)에 올렸다. 그 결과대로 고쳤다: 해독 대결 빈도 분석은 1:52~2:42(내용 맞음, 시작만 1초 뒤로), 스키테일 시연 첫 칸은 2:11~2:19에서 0:22~0:46으로(띠의 글자가 잘 안 보여서, 뒤섞인 암호문이 선명한 장면으로 바꿈), 둘째 칸은 끝을 2:40으로 늘림. 새 영상 구간을 넣을 때는 같은 방법으로 확인을 부탁한다. 배포 주소(ciphers-and-numbers.github.io)는 환경의 허용 주소에 넣어서, 배포한 뒤 이 환경에서 직접 열어 확인할 수 있다.
- 어사이드(선생님 컴퓨터의 브라우저 도우미)와 일 나누기: 직접 연결은 안 되므로 노션 "암호와 수 · 수업 영상 모음" 아래의 "어사이드에게 부탁할 일" 페이지를 사이에 둔다. Claude가 그 페이지의 "지금 부탁"에 확인할 주소·구간·보고 형식을 적고(상태: 부탁함), 선생님이 어사이드에게 그 페이지대로 해 달라고 말하면 어사이드가 같은 페이지의 "결과" 아래에 적는다. 선생님이 "어사이드 결과 확인해"라고 하면 Claude가 읽고 반영한 뒤 상태를 "반영함"으로 바꾼다. 유튜브 재생처럼 이 환경에서 못 하는 확인을 이 방법으로 맡긴다. 그 페이지에는 정답, 학생 이름, 제출 자료를 적지 않는다.
- 아홉 번째 학생 웹앱 `seed-cipher/`(10303 학생의 시드 암호)를 만들어 목록에 올렸다. 1기 10/6·10/19·10/27 요약에서 고름(이름은 학생이 붙인 그대로): 한글을 두벌식 자판에서 같은 자리의 영문으로 바꾼 뒤 시저 암호처럼 3칸 미는 2단계 암호이고, 업그레이드 "시큐어 시드 암호"는 자음 자리는 3칸, 모음 자리는 2칸 민다. 단계: 자판에 숨은 글자(한글 ↔ 영문) → 3칸 밀기(끝 글자는 처음으로) → 거꾸로 풀기 → 업그레이드와 숨은 문제 → 나만의 열쇠와 짝의 암호 → 마무리. 업그레이드를 계산해 보니 서로 다른 자모가 같은 암호 글자가 되는 쌍이 생겨서(곱셈 알파벳 암호의 "글자가 겹침"과 같은 문제), 이것을 도전 4의 탐구로 삼았다. 암호표는 문제를 하나 맞힌 뒤 열리고, 겹치는 칸의 색 표시는 쌍의 수를 맞힌 뒤에 나온다. 쌍자음과 ㅒ, ㅖ는 Shift가 필요해서 쓰지 않으며 그런 낱말을 넣으면 막는다(웹앱을 만들며 정한 것). 영문 답은 소문자·대문자 모두 맞게 정답 탭에 적었다. 화면 오른쪽 아래 버튼은 "자판"(자판 그림과 알파벳 순서). 짝의 낱말 채점은 학생이 쓴 한글을 다시 암호로 바꿔 비교한다. 정답 탭 14문항 등록, 휴대폰 폭 채점(14문항 모두 맞음)·제출·새로고침 시험 뒤 시험 기록을 지웠다.
- 열 번째 학생 웹앱 `starlight-cipher/`(10125 학생의 별빛 암호)를 만들어 목록에 올렸다. 1기 10/6·10/19 요약에서 고름(이름은 학생이 붙인 그대로): 한글 기본 자음 14개는 번호(ㄱ = 1 … ㅎ = 14), 모음은 별·하트·세모 같은 기호로 바꾼다. AI가 14를 1과 4로 잘못 읽은 일에서 학생이 찾은 약점 "기호가 여러 뜻으로 읽힌다"를 중심 탐구로 삼았다. 단계: 수와 기호 읽기 → 암호로 바꾸기(기호 버튼으로 완성) → 어디서 끊어 읽을까(붙은 수를 끊는 방법의 수) → 학생의 업그레이드 "자음 번호 × 2"로는 끊는 문제가 그대로임을 확인하고, 두 자리로 맞춰 쓰면 하나로 정해짐 → 나만의 별빛 암호(곱하는 수 1~6, 두 자리로 쓰기)와 짝의 암호 → 마무리. 웹앱을 만들며 정한 것: 모음 기호표(요약에 기호가 다 적혀 있지 않음. 닮은 모음끼리 채운 기호와 빈 기호로 짝지음), 받침은 모음 기호 뒤에 이어 쓰기, 두 자리로 맞춰 쓰는 해결 방법, 기본 자음·기본 모음만 쓰기(쌍자음과 ㅐ·ㅔ가 든 낱말은 막음). 암호문 칸 아래에 기호 버튼 줄이 있어 휴대폰에서도 기호를 넣을 수 있다. 오른쪽 아래 버튼은 "기호표". 정답 탭 12문항 등록, 휴대폰 폭 채점(12문항 모두 맞음)·제출·새로고침 시험 뒤 시험 기록을 지웠다.
- 공개 사이트 점검 반영(6가지): ① 시저 경계값을 "합이 26 이상이면 26을 뺀다"로 통일(포트폴리오, 시저 암호 공식, 두 열쇠 암호, 첫 화면 그림). A = 1부터 세는 학생 웹앱의 "26을 넘으면"은 그대로 맞으므로 두었다. ② 스키테일: 실제 막대는 "옆면 수", 2도 후보로 넣는 격자 문항(12글자 후보, 2라운드)은 "격자의 행 수"로 부른다. 12글자 후보는 1과 12를 빼고 2를 넣는다고 화면에 밝히고 정답 탭도 `2,3,4,6` 하나로 맞췄다. 배수 규칙 문장에 "마지막 바퀴의 빈칸까지 X로 채우면"을 넣고, 규칙 칸은 "옆면 수"도 맞음으로 받는다(입력 글자 수 3 → 6). ③ 소수·RSA 활동 2: 역할(곱하기/쪼개기/혼자)을 고르면 그 역할 문제만 보인다. 짝은 17 × 23과 391을 동시에 풀고 서로 보기 전에 각자 초시계로 잰다. 혼자는 곱한 뒤 다른 수 377을 쪼갠다. 숨은 역할 칸은 빈칸으로 세지 않는다. 활동 3의 N은 "공개하는 수"로 부르고, RSA의 소인수분해 어려움을 체험하는 모형이라고 밝혔다. 정답 탭에 `활동2 391/377` 4줄 추가(옛 `323` 줄은 남김). ④ 바코드: "올바른 바코드"를 "체크숫자 검사를 통과했어요"로, 판정 선택지 "정상"을 "검사 통과"로 바꾸고, 숫자 하나 바꾸기(찾아냄)와 이웃한 두 숫자 순서 바꾸기(1과 6, 합 19와 9, 통과)를 비교하는 상자를 사건 2에 넣었다. ⑤ 입구 암호(`gate.js` v3): "알파벳 표의 왼쪽으로 k칸 이동"과 예) F → A처럼 칸 수와 예시가 문제마다 함께 바뀐다. ⑥ 홈 검색 예시를 "한 학생의 작품 찾기"와 "반별 작품 찾기" 두 줄로 나눴다(검색 동작은 그대로).

- 열한 번째 학생 웹앱 `lamy-cipher/`(10601 학생의 LAMY 암호). 1기 10/6·10/19·10/27 요약에서 고름. 기본형은 A=1부터 번호를 붙여 낱말 끝자리에서 1을 빼고, AI가 단서를 찾아 해독한 일은 도전 3에서 다룬다. 해독 대결의 업그레이드는 도전 4에, 짝 교환은 도전 5에 넣었다. 웹앱을 만들며 정한 것: 1~26 순환, 낱말 안 하이픈·낱말 사이 쉼표, 낱말 안만 뒤집고 쉼표 앞과 문장 끝에는 서로 다른 값을 한 번씩 더하기. 학생 웹앱 10개의 규칙을 대조해 낱말 경계가 핵심인 작품을 추가했다.

- LAMY 암호 개선: 도전 2·4의 순환과 해독 순서 안내를 보강하고, 도전 3 정답 확인 뒤 낱말별 바뀐 자리와 남은 자리 수를 표로 보여 준다. 도전 5에서 학생이 계산을 맞히면 평문을 제외한 두 값과 암호문을 복사할 수 있다. 제출 문항과 정답은 그대로다.

- LAMY 암호 학생 동선 재검토: 도전 5에서 복사한 세 줄을 받는 쪽에 붙여 넣으면 두 값과 암호문을 나눠 입력한다. 기존 수동 입력도 사용할 수 있다. 번호표는 Esc로 닫을 수 있고, 모바일에서 확인 버튼과 화면 끝 여백을 확보했다. 답을 고친 뒤 이전 채점 응답이 도착하면 현재 입력에 그 결과를 표시하지 않도록 `common/submit.js`를 보강하고 LAMY 페이지의 파일 버전을 올렸다.

- 열두 번째 학생 웹앱 `tptp-cipher/`(10203 학생의 TPTP 암호). 10/6·10/19·10/27 요약에서 확인한 자모와 원소 기호의 대응, 규칙을 알려 준 뒤 AI가 해독한 일, 낱말 사이에 원소 기호를 끼운 업그레이드를 활동에 반영했다. 웹앱을 만들며 정한 것: 요약에 없는 기본 자모 대응표, 공백·빗금·세로줄 구분, 두 낱말 사이에 기호 하나를 독립된 묶음으로 끼우는 방식. 공개판 검토에서 띄어쓰기를 없애 비교하는 채점 규칙과 충돌한 문항을 ‘Co의 기호 개수’로 바꿨다. 도전 3은 기호와 음절의 경계, 도전 4는 끼운 묶음에 남는 단서, 도전 5는 암호화·해독 및 짝 교환이다.

**새 학생 웹앱을 만드는 순서**
1. 드라이브 요약에서 학생 암호를 고른다. 요약에 없는 세부 규칙을 정했으면 웹앱 첫 화면과 이 문서에 "웹앱을 만들며 정한 것"이라고 밝힌다.
2. 가장 가까운 기존 웹앱(`bracket-cipher/`, `caesar-prime-cipher/`, `seed-cipher/`, `starlight-cipher/`)을 복사해 공통 셸(`:root`, 상단바, 탭, 아래 고정 바, 번호표 버튼)은 그대로 두고 단계 내용과 도구 전용 JS만 바꾼다. 7단계 구성: 시작 → 도전 1~5 → 마무리와 제출. `CN.init({ lesson: "폴더이름" })`.
3. 확인 버튼(`data-check`) 문항의 답은 페이지의 계산 함수를 브라우저에서 실행해 구하고, 시트 `정답` 탭 맨 아래에 넣는다(행 범위를 정해 `update_values`로 쓰면 다시 시도해도 중복되지 않는다). 답은 저장소에 적지 않는다. 화면 문장이 답을 그대로 알려 주지 않는지도 본다.
4. Playwright로 휴대폰 폭(390×844) 시험: `chromium.launch({proxy:{server: process.env.HTTPS_PROXY}})`, `newContext({ignoreHTTPSErrors:true})`. 학번 칸에 시험 학번 10630, 모든 `[data-q]` 칸 채우기(서술형은 "시험"), 모든 `[data-check]` 누르고 옆의 `.check-mark`가 모두 `ok`인지, `#submitBtn` 뒤 `#submitStatus`가 "제출했습니다"인지, 별 5개와 잠긴 도구가 열렸는지, 페이지 오류와 가로 넘침(`scrollWidth` ≤ 390)이 없는지, 새로고침 뒤에도 표시가 남는지 본다. 시험 스크립트는 답이 들어 있으므로 저장소가 아니라 스크래치패드에 둔다.

6. 썸네일 `thumbnails/폴더이름.png`(1200×600, 답과 열쇠 수는 넣지 않음)를 HTML로 그려 Playwright로 찍는다. `site-config.js`의 `TOOLS` 끝에 항목 추가(`maker`에 학번), `index.html`의 `?v=` 올리기.
